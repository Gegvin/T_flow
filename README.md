## Интерпретатор T-Flow 

Это было тяжело и долго но вот он. Интерпретатор T-flow (С)


### `src/ast.rs`

структуры:

* `Program`
* объявления `state`, `node`, `grid`, `step`
* инструкции `let`, `next`, `return`
* выражения
* литералы
* операторы
* тернарный оператор
* режимы границ `wrap`, `clamp`, `fixed` - Это вот одна из тех вещей, что мы на защите про пространство симуляции говорили.

### `src/ast_parser.rs`

До этого в проекте уже был лексер и парсер для проверки кода. Но как мы на защите и сказали AST он не строил.

Я взял за основу парсер Паши и доработал до AST.

```text
parse_state -> StateDecl
parse_node -> NodeDecl
parse_grid -> GridDecl
parse_step -> StepDecl
parse_expression -> Expr
```

Старый `parser.rs` я оставил отдельно, чтобы не ломать diagnostics для VS Code. (но вот тесты для него убрал, там на меня Rust наругался)

### `src/interpreter.rs`

Что он умеет: 

* `state`
* `node`
* `grid`
* `step`
* `let`
* `next`
* арифметику
* сравнения
* тернарный оператор
* доступ к соседям через `x#[offset]`
* границы `#wrap`, `#clamp`, `#fixed(...)`

Идея - интерпретатор отдельно хранит текущее состояние и следующее состояние (фишечка наша). Когда встречается `next`, значение записывается в `next_values`, а после завершения шага становится новым текущим состоянием.

```text
values -> вычисление next_values -> обновление values
```

### `src/main.rs`

Добавил новые режимы запуска.

Печать AST:

```bash
cargo run -- --ast examples/ast_demo.tflow
```

Запуск интерпретатора:

```bash
cargo run -- --run examples/neighbors.tflow --steps 3
```

### `examples/ast_demo.tflow` 

Состояние увеличивается на 1 на каждом шаге.

### `examples/neighbors.tflow`

Каждая ячейка становится суммой себя и двух соседей

```text
left + center + right
```

За счёт `#wrap` границы заворачиваются по кругу. Уроборос местного разлива ещё и в 1d!!!

```text
step 0
x = [0, 1, 0, 0, 0]
step 1
x = [1, 1, 1, 0, 0]
step 2
x = [2, 3, 2, 1, 1]
step 3
x = [6, 7, 6, 4, 4]
```


### `tests/ast_parser_tests.rs`

Все тесты запускаются командой: 

```bash
cargo test
```

Тесты для Парсера.

* валидная программа превращается в AST
* в AST есть `StateDecl`, `NodeDecl`, `GridDecl`, `StepDecl`
* арифметика попадает в `Binary`
* тернарный оператор попадает в `Ternary`
* `x#[0]` попадает в `Spatial`

### `tests/interpreter_tests.rs`

Для интерпретатора. 

* обычное обновление состояния
* `#wrap`
* `#clamp`
* `#fixed`
* тернарный оператор

## Итог

Теперь путь программы выглядит так

```text
.tflow файл
-> lexer
-> AST parser
-> interpreter
-> результат выполнения
```
